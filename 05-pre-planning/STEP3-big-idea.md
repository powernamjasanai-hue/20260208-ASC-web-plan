## 1. 기존 시장의 일반적 접근

### AI 교육/커뮤니티 시장의 현재 포지셔닝

| 유형 | 대표 예시 | 핵심 메시지 | 한계 |
|------|----------|-----------|------|
| **AI 툴 교육** | ChatGPT 강의, 프롬프트 엔지니어링 | "이 도구를 쓰면 생산성 10배" | 도구만 알려주고 수익화 안 가르침 |
| **1인 창업 코칭** | 퍼널해킹, 인포프리너 | "이 방법으로 월 1000만원" | 과장 마케팅, 실제 성과 증명 부족 |
| **크리에이터 프로그램** | 글쓰기 챌린지, 콘텐츠 부트캠프 | "30일 만에 팔로워 1000명" | 단기 챌린지로 끝남, 수익화 연결 없음 |
| **코딩 부트캠프** | 바이브코딩 강의, 노코드 강의 | "코딩 없이 서비스 만들기" | 만들기만 하고 판매 미지원 |
| **커뮤니티/네트워킹** | 슬랙 그룹, 디스코드 | "같은 관심사의 사람들과 연결" | 구조 없이 자발적 참여에만 의존 |

### 시장의 공통 문제

```
"만드는 법"만 가르치고 "파는 법"은 빠져 있다.
 또는
"파는 법"만 가르치고 "만드는 법"은 빠져 있다.

→ 만들기(Build)와 팔기(Sell)를 하나의 구조로 연결하는 프로그램이 없다.
```

## 2. 문제의 재정의

### 기존 관점 (시장이 말하는 것)

> "AI 도구를 잘 쓰면 성공한다"
> "좋은 상품을 만들면 알아서 팔린다"
> "마케팅 스킬만 있으면 수익화된다"

### ASC의 재정의 (새로운 관점)

> **"문제는 AI 스킬이 아니다. '만들기 → 알리기 → 팔기 → 자동화'의
> 전체 구조가 연결되지 않으면, 아무것도 의미가 없다."**

### 재정의의 핵심 논리

```
일반적 접근:     스킬 A를 배우자 → 스킬 B를 배우자 → 스킬 C를 배우자
                (분절된 학습, 통합 없음)

ASC의 접근:     Creator(알리기) → Builder(만들기) → Sales(팔기) → AI Agent(자동화)
                하나의 선순환 구조 안에서 동시에 실행

일반적 접근:     혼자 독학 → 포기 → 다른 강의 → 또 포기
                (실행 환경의 부재)

ASC의 접근:     매달 코호트 → 조별 인증 → 그룹 컨설팅 → 1:1 피드백
                (실행을 강제하는 환경 제공)
```

## 3. 빅아이디어

### 한 문장 정의

> **"AI로 만드는 건 이미 누구나 할 수 있다.
> 진짜 차이는 '파는 구조'를 가진 사람과 가지지 못한 사람 사이에서 벌어진다.
> ASC는 1년간 만들기·알리기·팔기·자동화를 하나의 구조로 완성하는 유일한 실행형 커뮤니티다."**

### 빅아이디어 3요소 분해

| 요소 | 내용 |
|------|------|
| **기존 신념 파괴** | "AI를 잘 쓰면 돈을 벌 수 있다" → 아니요. AI로 '만드는 것'은 이미 쉬워졌어요. **파는 구조**가 없으면 만들어봤자 소용없어요. |
| **새로운 규칙 제시** | 성공하는 솔로프리너는 4개 역량(Creator/Builder/Sales/AI Agent)을 **동시에** 돌립니다. 하나만 잘해서는 안 돼요. |
| **유일한 해결책** | ASC는 이 4개를 **1년간 선순환 구조**로 실행하게 만드는 유일한 환경이에요. 강의가 아니라, 실행 환경이에요. |

### 빅아이디어가 각 ICP에게 작동하는 방식

```
ICP A (만들었는데 안 팔림):
"아! 나는 Builder만 했고 Sales가 빠져있었구나.
 ASC에서 Sales 트랙을 하면 파는 구조가 만들어지겠다."

ICP B (팔로워만 있음):
"아! 나는 Creator만 했고 Builder + Sales가 빠져있었구나.
 오디언스를 수익으로 연결하는 구조를 배울 수 있겠다."

ICP C (시작 전):
"아! 처음부터 4개를 순서대로 따라가면 되는구나.
 혼자 고민하지 말고 구조 안에서 시작하면 되겠다."
```

## 4. 설득 프레임워크 선정

### 메인 프레임워크 (전체 페이지 관통)

| 프레임워크 | 적용 방식 |
|-----------|----------|
| **WHY-HOW-WHAT** | 왜 필요한지 → 어떻게 작동하는지 → 무엇이 포함되어 있는지 |
| **PASONA** | Problem → Agitation → Solution → Narrowing → Action |
| **사회적 증거 기반** | 매 3~4섹션마다 후기 브릿지 배치 |

### 섹션별 서브 프레임워크

| 페이지 위치 | 프레임워크 | 역할 |
|------------|-----------|------|
| 상단 (Hook) | **문제-솔루션** + **반상식** | "만드는 게 문제가 아니에요" 로 기존 믿음 파괴 |
| 중단 (Educate) | **비교 기반** + **앵커링 효과** | 혼자 vs 함께, 다른 프로그램 vs ASC |
| 하단 (Convert) | **손실 회피** + **희소성** + **미루기 방지** | 가격 상승 예고 + 인원 제한 + 환불 보장 |

### 헤드카피 후킹 유형 배치 전략

| 섹션 위치 | 후킹 유형 | 이유 |
|----------|----------|------|
| Hero | **반상식 + 문제 기반** | "AI로 만들었는데 안 팔렸다면" — 기대 뒤집기 |
| 문제 정의 | **공감 유발 + 체크리스트** | "이런 경험 있으시죠?" — 자기 인식 유도 |
| 솔루션 | **솔루션 기반 + 숫자** | "4개 트랙으로 완성" — 구체성 + 체계성 |
| 멤버 스토리 | **성과 + 스토리텔링** | "2개월 만에 180도 바뀌었어요" — 감정 이입 |
| 가격 | **비교·대조 + 욕망** | "혼자 학습 vs 함께 실행" — 선택 프레이밍 |
| Final CTA | **트렌드 + 강한 주장** | "역사상 처음인 이 타이밍" — 긴급성 |

## 5. 콘텐츠 기획법 적용 전략

### 헨젤과 그레텔 기법 — 도파민 빵조각 설계

```
페이지 전체 흐름:

[Hook] "AI로 만들었는데 안 팔렸다면"
  → 빵조각: "그런데, 문제는 AI가 아니에요..."
[Problem] "만드는 건 쉬워졌는데 파는 건 여전히 어렵죠"
  → 빵조각: "어디에 해당하시든 괜찮아요. ASC가 설계된 이유예요..."
[Solution] "4개 트랙으로 함께 완성해요"
  → 빵조각: "실제로 이 구조를 따라간 분들의 이야기를 들어보세요..."
[Stories] "여기서 시작해, 여기까지 오신 분들이에요"
  → 빵조각: "이분들이 특별했던 게 아니에요. 환경이 달랐을 뿐이에요..."
...계속 다음이 궁금하게
```

### 제이가르닉 효과 — 미완성 정보 배치 포인트

1. Hero 섹션: "만든 것을 파는 구조" → 구조가 뭔지는 아직 안 알려줌 (→ S4에서 해결)
2. Solution Overview: 4트랙 소개 → 실제 성과는 아직 (→ 후기 브릿지에서 해결)
3. Pricing 전: "이만큼 포함되어 있다" → 가격은 아직 (→ 스크롤 유도)

### 셀프-레이블링 효과 — 정체성 부여 시점

- S3(문제 정의): "당신은 이미 시작한 사람이에요" (ICP A에게)
- S8(Peer Group): "이런 분들과 같은 테이블에 앉는다면" (소속감)
- S12(Exclusivity): "진짜 기업가로 성장하고 싶은 분" (정체성 업그레이드)
